# Name Arena：AI DM 最小原型

沿用原竞技场的名字生成角色与战斗系统，增加独立的单人冒险流程。基线为主分支提交 `32537fe2d2013607e5bcdd491626d591c1bd8602`。没有改动原 `index.html` 或 Pages 部署配置。

## 最快开始

安装 **Node.js 24 或更高版本**，确认 `node --version`。项目没有第三方 npm 依赖，不需要执行 `npm install`。

```bash
git clone --branch codex/ai-dm-prototype https://github.com/Isabelle20070607/Name_Arena_in_DND.git
cd Name_Arena_in_DND
npm run demo
```

打开 <http://127.0.0.1:3000/adventure/>。输入角色名字并创建，等待开场；依次试试“调查石碑”“与林恩交谈”“攻击拦路强盗”“在旅店休息”。刷新页面、关闭并重启服务后，可从“冒险存档”选择战役继续。

**演示模式使用明确标注的固定剧情，不调用 AI，也不产生 API 费用。** 它用于验证页面、骰子、战斗、存档和恢复流程；演示剧情不理解任意行动或自定义设定。

原有五种模式仍可直接打开根目录 `index.html`，或在本机服务中访问 <http://127.0.0.1:3000/arena/>。

## 使用真实 AI DM

1. 停止演示服务：终端按 Ctrl+C。
2. 把根目录 `.env.example` 复制为 `.env`。Windows PowerShell 使用 `Copy-Item .env.example .env`；macOS/Linux 使用 `cp .env.example .env`。
3. 在本机 `.env` 填入自己的 API 密钥和可用模型。模型需要支持 **Responses API + Structured Outputs**。示例模型标识来自官方文档，实际权限以你的 API 项目为准。

```dotenv
OPENAI_API_KEY=填入你的密钥
OPENAI_MODEL=gpt-6-astra
PORT=3000
```

```bash
npm start
```

打开相同的本机地址，页面右上角应显示“AI DM”。创建新的战役，填写想要的开场设定，再连续输入自己的行动。

`.env` 只在 Node 服务端读取，已被 `.gitignore` 忽略。前端不接收密钥，不直接调用 OpenAI。API 地址固定为 `https://api.openai.com/v1/responses`；不支持由浏览器指定任意代理地址。修改密钥、模型或其他环境变量后需重启服务。

正常行动通常调用模型两次：一次提出规则裁定，一次根据服务端结果续写；开场一次。设置 `store:false`，应用自己管理上下文；这不代表关闭 API 服务商的全部数据保留机制。默认每次输出上限 4000 tokens，超时 60 秒，可在 `.env` 修改 `OPENAI_MAX_OUTPUT_TOKENS`（512–16000）及 `OPENAI_TIMEOUT_MS`（1000–180000 毫秒）。项目未设置每月消费硬上限。

## 实际复用了什么

以下位置对应未改动的原 `index.html`，而非仅根据 README 推断。

| 原代码 | 位置 | 在冒险中的用途 |
| --- | --- | --- |
| `NameHasher` | 2006 行起 | FNV-1a、种子 RNG、4d6 去最低、能力值生成、单骰 |
| `Character` | 3028 行起 | 角色能力、五级职业和子职业、HP、AC、攻击、职业资源 |
| `mod` / `assignClass` | 3167 / 3175 行起 | 属性修正与职业选择 |
| `CombatEngine` | 3206 行起 | d20、命中、伤害、豁免、状态、职业行动与事件日志 |
| `CombatEngine.fight` | 3521 行附近 | 参考遭遇循环；它会重置 HP，因此冒险不直接调用它 |

`scripts/extract-arena.cjs` 从真实 HTML 中生成 `adventure/lib/arena.cjs`。它把中文语言状态改为服务端常量，并将武僧震慑打击里的一处 `Math.random()` 改为该次遭遇的 `eng.rng()`，便于稳定重试。这两项适配仅出现在新模块。原 Boss 定义保留在生成内容中，但不对外导出，也不用于冒险；其中未迁移的随机机制不在本原型调用路径内。

```bash
npm run engine:check     # 检查生成模块是否仍与原 HTML 及这两项适配一致
npm run engine:extract   # 以后修改原规则时重新生成模块，随后检查 diff
```

**原代码没有通用冒险技能检定。** `Character.skills` 是战斗能力，不能直接当作“调查、隐匿”等技能熟练。因此本原型新增三种明确标注的背景：旅人（察觉、求生）、学者（奥秘、调查）、使者（洞悉、游说）。对应技能使用原角色的熟练加值，其余用属性修正。这是原型规则，不是声称实现了完整官方建卡流程。同名角色的能力、职业、子职业等仍与竞技场一致；角色和冒险状态一起载入。

## 一回合怎样运行

1. 浏览器发送行动文本、请求 UUID 和当前存档版本。
2. DM 输出结构化计划：无需检定、一次属性/技能检定、一次自动战斗，或安全休整。
3. 服务端校验计划。检定使用 `d20 + 属性修正 + 适用的背景熟练加值 ≥ DC`，支持优势/劣势；普通能力检定的自然 20/1 不自动成功/失败。战斗调用原引擎的命中、伤害、豁免与职业能力。
4. 服务端把计划、骰子结果和结算后状态暂存，再让 DM 根据确定结果续写。模型不能返回任意 HP 修改或可执行代码。
5. 叙事通过校验后，一次 SQLite 事务保存角色、世界、摘要、事实、完整回合及请求状态。页面显示“已保存”。

同一请求重复发送不会创建两个回合。页面、刷新或服务器重启后，尚未完成的续写可以使用原请求重试，沿用同一检定及战斗结果。也可取消未完成回合，回到上次完整存档；取消的请求 ID 不能重用。提交过期版本或同时提交两项行动会被拒绝。

若第一阶段计划失败，尚未发生结算，可以重新提交。若第二阶段失败，页面显示“重试续写”和“取消未完成回合”；不要仅靠新行动绕过这个待处理回合。HTTP 401 通常需要检查密钥，429 需要检查额度或限流；输出未完成时可考虑调整输出上限。服务端不会把服务商返回的原始错误体或密钥发送给页面。

## 存档与记忆

- 真实模式默认保存到 `data/campaigns.sqlite`，演示默认 `data/demo.sqlite`。如果显式设置 `SAVE_DB`，两者都会使用该路径；建议保持默认或分别指定。演示战役只能在演示模式继续，真实战役只能在真实模式继续。
- 每回合保存角色剩余 HP、临时 HP、有限技能及职业资源；保存当前地点、目标、物品、累计安全休整小时数和累积摘要。
- 所有完成回合与新增事实持续保存在 SQLite。每次提示包含最近 8 回合、累积摘要、最初/最近事实，以及按中英文关键词匹配检索出的旧事实。
- 页面每次先载入最近 50 回合，可读取更早记录。导出按钮生成包含完整状态、对话、结算与事实的 JSON 阅读归档；本版尚无 JSON 导入界面。
- **完整恢复请备份数据库**：先停止服务，再复制整个 `data` 目录；恢复时把它放回相同代码版本的仓库目录。`data` 和 `.env` 均不提交到 Git。保存格式及规则版本有检查，不兼容版本会明确报错。

记忆检索是便于维护的关键词方案，没有外部向量数据库。摘要和事实由模型提取，仍可能遗漏或写错；“持久保存”不等于保证模型永远不会忘记或产生矛盾。可以在“旅程记忆”和完整归档中查看它的记录。

## 规则范围

保留原竞技场的自定义简化 5e 机制，固定五级。战斗自动结算整场，提供三档服务端敌人模板；不会把玩家自然语言转成任意代码或任意敌人数值。角色 HP 和有限资源在遭遇间延续，临时条件和短期战斗增益按遭遇处理；安全休整八小时恢复 HP 与资源。

本版不提供完整 2024/SRD 规则覆盖、手动逐轮战斗、升级、施法/装备完整管理、物品数值效果或死亡豁免。0 HP 表示失去行动能力，可由叙事安排救援，再在安全地点休整。DM 的非战斗叙事不会额外扣血/治疗；数值结算以规则记录为准。原战斗引擎已有的简化和规则偏差仍可能存在。

地图编辑、语音、大型 NPC 系统不在本次范围内。

## 文件与扩展位置

| 文件 | 职责 |
| --- | --- |
| `adventure/server.cjs` | 本机 HTTP 服务、静态白名单、API 路由和输入边界 |
| `adventure/lib/arena.cjs` | 从原 HTML 生成的角色、骰子与战斗规则 |
| `adventure/lib/rules.cjs` | 冒险检定、角色状态恢复、敌人模板与连续 HP/资源适配 |
| `adventure/lib/contracts.cjs` | 模型输出 Schema 和服务端校验 |
| `adventure/lib/dm.cjs` | OpenAI Responses 代理、两阶段提示词、离线演示 |
| `adventure/lib/campaigns.cjs` | 回合编排、幂等、版本、记忆上下文 |
| `adventure/lib/store.cjs` | SQLite 存储与事务 |
| `adventure/public/` | 无构建工具的冒险页面 |
| `adventure/test/prototype.test.cjs` | 规则复用、HTTP、持久化及失败恢复测试 |

服务仅绑定 `127.0.0.1`，拒绝非本机 Host 与跨站请求；不提供公网多用户认证。用单个 Node 进程运行即可。静态服务只允许冒险页面资源和旧竞技场 HTML，不暴露 `.env`、源码或数据库。
